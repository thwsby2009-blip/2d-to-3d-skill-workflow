# 2D 四視圖 → 3D 模型：技術文件

> 適用：由同一角色的**正交四視圖**（正面／背面／左側／右側）點陣圖，重建可編輯的 3D 網格＋材質。
> 實作環境：Blender 5.0.1 headless（`blender -b -P script.py`）、系統 python3 純 PIL 量測。
> 案例來源：紅色金屬植物機器人（2026-09）、綿羊（2026-11）。
> 定位：**輪廓驅動的參數化重建**——不是 AI 生成，所有幾何都是量測值的函式，可逐版重跑、可回溯。

---

## 0. 方法的一句話

**用「正面剪影決定左右寬度、側面剪影決定前後深度」，沿高度逐層掃掠斷面。**
兩張正交剪影同時被滿足，這是整個方法的地基；其餘都是修正它的副作用。

| 適合 | 不適合 |
|---|---|
| 單一主體、近凸形（圓胖角色、動物、蔬果、機械殼）| 遮擋複雜（手抱物、尾巴繞身、多層衣物）|
| 四視圖風格一致、主體完整入鏡 | 四視圖互相矛盾到無法調和 |
| 外部形狀就是設計主體 | 內部結構是重點（剖面圖、機構）|

## 1. 素材品管：先驗收，再動手

**不要拿到圖就開始建模。** 先用程式量出素材的「可用性分數」，不合格就回去重生成。

### 1.1 三項一致性檢查

| 檢查 | 算法 | 範例值（綿羊）| 判定 |
|---|---|---|---|
| 前／背一致性 | 各自 W/H 比值差 | 0.634 vs 0.630（差 0.7%）| ✅ |
| 左／右一致性 | 各自 W/H 比值差 | 0.722 vs 0.725（差 0.3%）| ✅ |
| 四張總高 | 主體 bbox 高度差 | 473px vs 443px（差 6.8%）| ⚠️ 見下 |

前後／左右配對誤差 <2% 就可以用；>5% 表示 AI 畫的四視圖不是同一隻，重建會出現矛盾。

**總高不一致要查原因，不要直接縮放。** 綿羊的 6.8% 來自**側面是走路姿勢**（腿張開→身體離地較近→總高較小）。
處理原則：**以「正面」為姿勢基準**（四足動物的正面／背面通常是站姿），側面只用來取「深度」資訊，高度軸改用身體高度對齊。

### 1.2 慣例與標籤檢查

- 角色面朝 −Y 時，**左側視圖的鼻尖應該出現在畫面左邊**。綿羊素材剛好相反（標籤與慣例對調）——不影響建模（左右剪影互為鏡像），但**必須記錄**，否則後續討論會溝通錯方向。
- 有對齊輔助線／尺寸標註時：
  - 標註數字（如「100」）**不能直接相信**，要用像素實測驗證（本案標 100 但實際差 6.8%）。
  - 輔助線是灰色細線，用**顏色通道**就能自動排除（見 1.3）。

### 1.3 主體／背景自動分離

描邊插畫的主體是暖色（奶油、橙、棕），背景是中性灰：

```python
def is_warm(px, x, y):          # 主體遮罩
    r, g, b = px[x, y]
    return (r - b) > 22 or (r - g) > 18

# 背景 (241,241,241) → r-b=0 排除；灰輔助線 → 排除；紅色標籤文字 → 要另外擋掉
```

**陷阱**：底部紅色標籤（「左側」「右側」）也符合暖色條件 → 逐列投影時會把標籤算進輪廓。
解法二選一：(a) 裁掉標籤所在的列；(b) 取「含主體的最長連續段」而不是全圖 bbox。

```python

    ...  # 取最長段 = 主體；離散的短段（文字）自動被排除
```

### 1.4 切格

四視圖若在同一張圖（2×2 格），先找分隔線再切：

```python
# 掃中央區域，找「整行/整列都是暗像素」的位置

    if sum(1 for x in range(W) if sum(px[x, y]) < 450) > W*0.9:
        dy = y      # 水平分隔線
```
本案：col 447-448、row 599-600。切完存成 `front/back/left/right.png` 四張單圖。

## 2. 座標系與尺度換算

```
       +Z (上)                    模型座標
        |                        X：左右（正面圖的 x）
        |                        Y：前後（+Y 朝臉／口鼻）
        |                        Z：上下（地面 z = 0）
        +------ +Y (前)
       /
     +X
```

### 2.1 換算常數

| 常數 | 定義 | 說明 |
|---|---|---|
| `S` | `H_model / body_height_px` | 正面像素 → 模型單位。**用身體高度（腹底→頭頂），不是總高** |
| `K` | `front_body_px / side_body_px` | 側面像素 → 正面像素。用「身體高度」對齊，可吸收走姿／總高差 |
| `CY` | 側面圖中「身體最寬列」的中點 x | 側面 Y 的原點 |
| `Z_BELLY` | 腹底高度（＝腿長）| 地面 z=0，腹底 z=Z_BELLY |

```python
S  = 0.005556          # H_model=2.15 對應 body 387px
K  = 1.1057            # 387/350
CY = 233.0
Z_BELLY = 0.417        # 腿長（腹部到地面）
```

### 2.2 逐點換算

| 來源 | 模型座標 |
|---|---|
| 正面圖像素 `(x, y)` | `X = (x - body_cx) · S`，`Z = (ground_y - y) · S` |
| 側面圖像素 `(x, y)` | `Y = (x - CY) · K · S`，`Z = Z_BELLY + (side_bottom_y - y) · K · S` |

**關鍵**：正面的 Z 與側面的 Z 必須落在同一個高度軸上。做法是**兩邊都用身體高度參數化**：
`u = (z - Z_BELLY) / BODY_H ∈ [0, 1]`（0 = 腹底、1 = 頭頂），再回推各自的像素列。

### 3.1 逐列掃描 → 半寬剖面


### 3.3 急轉折要先預平滑，否則會變成「整圈環狀摺痕」

**這是最容易踩的坑。** 側面剪影在「下巴／口鼻下緣」常有 10px 內 40px 的急收：

```
y=744: 前緣 397     ┐
y=754: 前緣 392     ├ 突然內收 40px
y=764: 前緣 352     ┘
```

斷面模型把側面前緣套用到**整圈** → 半徑在 10px 高度內整圈縮 0.24 單位 → 3D 表面出現一圈像「衣領」的台階。

**解法**：對側面剖面表做 `[1,2,1]/4` 預平滑（2 次），把 40px 的階梯攤成 30px 的斜坡：

```python
def smooth_col(tbl, idx, passes=1):
    for _ in range(passes):
        vals = [r[idx] for r in tbl]
        new[i] = (vals[i-1] + 2*vals[i] + vals[i+1]) / 4
```
平滑後前緣變成 `397 → 381 → 366 → 354`，摺痕消失、口鼻突出仍保留。

### 3.4 附屬件（耳朵、尾巴）不進主剖面

耳朵在正面剪影會**假性加寬頭部**（本案：頭寬 96px 被算成 126px）。
做法：主剖面的耳朵區段用「不含耳」的平滑估計值，耳朵另建獨立物件（見 §5.2）。

## 4. 建模核心：斷面掃掠

### 4.1 公式

對每個高度參數 `u ∈ [0,1]`：

```
hw(u)  = FRONT(正面列) · S                  # 半寬（X 方向）
yf(u)  = (SIDE 前緣 · K · S) − CY·K·S       # 前緣 Y
yb(u)  = (SIDE 後緣 · K · S) − CY·K·S       # 後緣 Y
yc(u)  = (yf + yb) / 2                      # 斷面中心
rd(u)  = (yf − yb) / 2                      # 半深（Y 方向）

斷面點(θ) = ( hw·cosθ,  yc + rd·sinθ,  z(u) )      θ ∈ [0, 2π)
```

環段數：本案 80（繞圈）× 96（沿高度）。頂點數約 7.7k，模型夠輕。

### 4.2 為什麼這招有效（也哪裡會失效）

- **有效**：兩個正交剪影被**精確**滿足（不是逼近）。這是本方法最大的優點——輪廓誤差可以直接量到 2% 以內。
- **失效**：橢圓斷面是「猜」的。剪影沒有任何資訊能約束它，所以：
  - 凹面（腰身、凹槽）不會出現——斷面永遠是凸的
  - 側面急轉折會整圈外擴（§3.3 的摺痕）
  - 兩個剪影矛盾時，橢圓斷面會選一個「中間解」，可能在兩邊都不像

### 4.3 收尾（頂/底）

```
底部：4 環 + 中心點，半徑縮放 [1.00, 0.92, 0.72, 0.40]，下沉 0.16
頂部：輪廓本身先收（頂段半寬提前變小）＋ 5 環 cos 縮放 + 頂點
```

**教訓（v10 失敗）**：若輪廓在頂部還是寬的（如半寬 0.194），才開始用 cos 收尾，等於做了一個**平頂圓盤**——
Freestyle 描邊會把它畫成「屋頂折角」，比不收尾更糟。
**正解**：讓**輪廓自己先收**（本案正面頂段 `97→20、107→30、117→40`），圓頂只是把剩下一小段收乾淨。

## 5. 附屬特徵

### 5.1 貼合曲面的色塊（臉部）

平面貼片放在曲面上一定會「中間浮起、邊緣沉入」或「中角被切」。
**正解**：不要用平面片，直接用**表面函數**生成。

```python
def surf_front(x, z):
    """頭部前表面在 (x, z) 的 Y"""
    hw, yc, rd, _ = cross_section((z - Z_BELLY) / BODY_H)
    t = min(abs(x) / hw, 0.9995)
    return yc + rd * math.sqrt(1 - t*t)          # 橢圓斷面的前弧
```

色塊網格 = 在 (X, Z) 平面上畫橢圓（同心環），每個頂點的 Y 用 `surf_front + 外移量(0.008)`；
最外圈再往**殼內縮 0.03** 做裙邊，閉合成薄殼 → 邊緣不會有陰影破口。

### 5.2 對稱件：由「基部／尖端座標」反推參數

耳朵不是憑感覺調角度，用原圖兩個點就能解出來：

```
基部 (X 0.164, z 2.20)      尖端 (X 0.386, z 2.494)
→ 長度 = √(0.222² + 0.294²) = 0.368 → 半長 0.184
→ 傾角 = atan(0.222/0.294) = 37°
→ 中心 = 兩點中點 (0.275, 2.347)
→ 扁橢球 scale = (半寬 0.070, 厚 0.030, 半長 0.184)，rot = (後傾 12°, 外張 37°)
```

### 5.3 細節線（鼻線、嘴弧、尾巴）

用**密集小球串成線**——條件是**球半徑 > 取樣間距**，否則會看到「一顆一顆」。

```python

    ...
# 鼻線：5 個控制點 → 內插 4 倍 → 17 顆 r=0.007（間距 0.005 < r ✅）
```

尾巴捲曲：沿圓弧參數化，半徑由粗到細：

## 6. 材質：原圖取色 ＋ 本色驗證

### 6.1 取色（區域平均，不看單點）

```python
region(x0,y0,x1,y1, skip_dark=430)   # 區域平均，跳過描邊暗像素
```
本案：身體 (251,234,208)、臉 tan (237,214,182)、腿橙 (236,150,103)、尾棕、描邊暗 (117,73,50)。

### 6.2 sRGB → linear（Blender 的 Base Color 吃 linear）

```python
def lin(v):
    c = v/255
    return ((c+0.055)/1.055)**2.4 if c > 0.04045 else c/12.92
```
例：(237,214,182) → (0.8469, 0.6724, 0.4678)

### 6.3 **平光檢查圖**：把「本色」和「打光」分開量

**坑**：打光過曝時，tone mapping（Khronos PBR Neutral）會壓縮 R 通道 →「奶油 vs tan」的色差被吃掉，
驗收時會誤判成「材質沒上上去」。

**解法**：另出一組檢查圖 —— 均勻白光 + `Standard` 轉換 + 關掉所有燈：

```python
for o in bpy.data.objects:
    if o.type == 'LIGHT': o.hide_render = True
world.node_tree.nodes["Background"].inputs[0].default_value = (1,1,1,1)
scene.view_settings.view_transform = 'Standard'
```
此時**像素值 ≈ 材質本色**，可直接跟色票對。本案驗證：臉/身線性比 0.874 vs 色票比 0.878 ✅
（引擎本身另有約 ×0.83 的系統性擴散係數，各材質一致，可忽略。）

## 7. 驗收方法（本方法的核心價值）

### 7.1 輪廓疊合：以高度正規化、底對齊、逐高度比寬度

```python
scale = ref_height_px / render_height_px
for k in range(5, 100, 5):                      # 從底部算 k% 高度
    ref_w = ref_profile[row_ref(k)][1] - ref_profile[row_ref(k)][0] + 1
    mod_w = render_profile[row_mod(k)][1] - ...  # 換算回原圖尺度
    print(誤差 = (mod_w - ref_w) / ref_w * 100)
```
輸出「平均|誤差|」與「最大誤差＋位置」。本案最終：**正面 2.2%、側面 9.2%**。

### 7.2 部位特徵：一律換算成「身高為單位」的比值

| 項目 | 原圖 | 模型 | 判準 |
|---|---|---|---|
| 臉塊高/身高 | 0.171 | 0.170 | ✅ |
| 眼球高度 z | 2.294 | 2.290 | ✅ |
| 眼球間距 | ±0.072 | ±0.075 | ✅ |
| 腿內側/外側 X | ±0.098 / ±0.336 | 同 | ✅ |

### 7.3 紀律

1. **分開「腳本執行成功」與「外觀驗收通過」**——腳本跑完不印 Error ≠ 做對了。
2. **一次只改一個主要變數**，改完重新量。本案 v10 一次改了頂部收尾，結果變差，才能歸因到收尾方式。
3. **失敗版全部保留**（`.blend` + 腳本），可回溯比較。
4. **任何零件都有三個獨立檢查項**：①本身尺寸 ②渲染中的可見尺寸 ③外輪廓形狀。只驗一項就會「修好一處又退回另一處」（機器人鼻子的教訓）。
5. 名稱有歧義時（模型有多個水平特徵），**先在既有視圖上標 A／B 給人確認再動手**。

## 8. 環境與工具陷阱（Blender headless）

| 陷阱 | 症狀 | 解法 |
|---|---|---|
| 只能 Cycles CPU | EEVEE/互動視窗起不來（`epoxy_get_proc_address` assertion）| `scene.cycles.device='CPU'`，一切走 `-b` 背景算圖 |
| 相機朝向 | 正面圖拍到背面 | 明確定義「+Y = 臉」，正面相機放 `+Y`：`(0, +8, CZ)`、rot `(90°, 0, 180°)` |
| 材質建立時機 | `open_mainfile()` 前建的 datablock 失效 | 材質一律在開檔後才建 |
| `use_nodes` 棄用警告 | 只是 warning，不影響 | 可忽略 |
| Freestyle lineset | `ls.linestyle` 是 `None` → 指派 color 爆 AttributeError | 要顯式建：`lsty = bpy.data.linestyles.new(...)`；`ls.linestyle = lsty` |
| Freestyle 描邊設定 | 需要輪廓+邊界線 | `select_silhouette/border/crease = True`、`line_thickness_mode='ABSOLUTE'` |
| 算圖批次 | 物件未套用縮放就算 bbox | 先 `bpy.context.view_layer.update()` 再讀 `matrix_world` |
| 渲染耗時 | 5-10 張圖 3-6 分鐘 | terminal timeout 設 560-600（超過 600s 會被轉背景程序）|

- shell heredoc 會被 Hermes 擋 → 一律 `write_file` 寫腳本再執行。

## 9. 匯出與交付（3D 檔案）

`.blend` 只是工作檔（只有 Blender 開得起來）。要交付／給人看，一定要另出通用格式。

### 9.1 出什麼

| 格式 | 內容 | 用途 |
|---|---|---|
| **GLB** | 幾何＋材質（PBR）＋物件階層，單一檔 | **首選**：任何 3D 檢視器、網頁檢視器、Unity/Unreal、Windows「3D 檢視器」|
| OBJ + MTL | 幾何＋材質（Kd 色）| 老軟體、C4D / Maya / 3ds Max |
| STL | 純幾何（無材質）| 3D 列印切片軟體 |
| PLY | 純幾何（二進位）| 寫程式讀取、點雲工具 |

### 9.2 Blender 5 的匯出 API（與 3.x 不同）

```python
bpy.ops.wm.obj_export(filepath=..., export_selected_objects=True, export_materials=True)
bpy.ops.wm.stl_export(filepath=..., export_selected_objects=True, ascii_format=False)
bpy.ops.wm.ply_export(filepath=..., export_selected_objects=True)
```

- **4.0 起 `export_scene.obj` / `export_scene.stl` 已移除**，改用 `wm.*_export`
- 匯出前 `select_set(True)` 只選網格，避免把燈光／相機一起帶進檔案
- 材質跟著 GLB／OBJ 走；**STL 沒有材質**（純幾何）

### 9.3 單位與尺寸

- glTF 單位是**公尺**：模型總高 2.622 → 檢視器會顯示成 2.6 m（只影響顯示，不影響比例）
- 列印要的是 mm：**出一個顯式縮放版**，不要讓下一個人自己換算
  ```python
  k = 100.0 / 總高                      # 縮到 100 mm
  obj.scale = (k, k, k)
  bpy.ops.object.transform_apply(scale=True)
  ```
- STL 匯出前可先 `bpy.ops.object.join()` 合成單一網格（切片軟體較好處理）

### 9.4 驗證：不要只看「匯出成功」

| 檢查 | 方法 |
|---|---|
| **GLB 結構** | 讀 12 byte header：`magic='glTF'`、`version=2`、**宣告長度 == 檔案實長**；再解 JSON chunk 數 nodes / meshes / materials |
| **OBJ** | 數 `v` / `f` 行；確認 `mtllib` 指向存在的 `.mtl`；`usemtl` 用到的材質名都在 MTL 內 |
| **STL** | 讀 84 byte header 的三角面數，再用 `struct.unpack('<12f', ...)` 逐面掃 bbox → **確認縮放後的實際尺寸**（本案 100mm 版實測高度 100.000）|
| **往返驗證（最強）** | 把 GLB 匯入**乾淨場景**重算圖：物件數、bbox、材質 Base Color 是否與原檔一致 |

```python
bpy.ops.wm.read_factory_settings(use_empty=True)     # 乾淨場景
bpy.ops.import_scene.gltf(filepath="...glb")
# 比對 bbox 與每個材質的 Base Color，再算 3 個角度確認無缺件
```

本案往返驗證結果：78 網格 / 5 材質 / bbox 完全相同（X±0.822、Y −0.936…+1.009、Z 0…2.622）/
5 個材質的 Base Color 逐項一致 ✅ → 匯出檔忠實。

## 10. 方法極限（誠實條列）

1. **視覺外殼（visual hull）本質**：兩個正交剪影只能約束「外接盒」等級的資訊，3D 形狀仍有無窮多解。
   橢圓斷面是**工程選擇**，不是唯一正解。想要更準就得加視角、加約束（對稱性、斷面形狀假設）。
2. **凹面與遮擋無法還原**：手抱在胸前、尾巴繞過身體，剪影只會給出融合成一團的外形。
3. **四視圖矛盾時必須選邊**：本方法的預設規則是「正面／背面為姿勢與比例基準，側面只提供深度」。
   若側面是動態姿勢（走姿、跳姿），就只能取身體比例，姿態另定。
4. **2D 插畫特徵不是幾何**：描邊線、身體漸層、光暈——描邊可用 Freestyle 重現（渲染層），漸層要靠材質或忽略。
5. **AI 生成的四視圖不一致是常態**：耳朵左右不對稱、臉部偏移（本案臉偏左 13px）、同一部位在不同視圖尺寸不同。
   原則：**配對視圖取平均、對稱件強制對稱**，並把偏差寫進文件。

## 11. 可複用 SOP（一頁）

```
□ 1 素材品管：前/背、左/右 W/H 一致性 <2%；查總高差原因；確認標籤慣例
□ 2 切格、存四張單圖；確認主體/背景可用顏色通道分離
□ 3 逐列掃描得 FRONT(半寬) / SIDE(前後緣) 剖面表
□ 4 定 S、K、CY、Z_BELLY；建立 u（身體高度參數）統一座標
□ 5 剖面表預平滑（[1,2,1]/4 ×2）→ Catmull-Rom 內插
□ 6 斷面掃掠建主體；底部/頂部收尾（頂部要讓輪廓自己先收）
□ 7 算一張正交圖 → 輪廓疊合驗收（平均誤差 >5% 就回頭修剖面表）
□ 8 加附屬件（腿/耳/尾）：位置由原圖兩點反推，對稱件強制對稱
□ 9 臉部/色塊：用 surf_front(x,z) 貼合曲面 + 裙邊
□ 10 取色（區域平均、跳過描邊）→ sRGB→linear → 上材質
□ 11 平光檢查圖驗本色；打光圖驗外觀
□ 12 逐版印數值驗收（跳階量、貼合距離、長度、角度）——不靠目測
□ 13 一次一變數；失敗版保留
□ 14 匯出通用格式：GLB（材質）＋ OBJ/MTL ＋ STL（另出列印尺寸版）
□ 15 驗收匯出檔：GLB header/節點數、STL 三角面數與實際尺寸、**GLB 往返匯入重算圖**
□ 16 凍結 RELEASE：.blend + sha256 + RELEASE.md + scripts/ + views/ + 匯出檔
```
